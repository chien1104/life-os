## 1. 產品定位與現況

### 1.1 產品定位（已確認）
Life OS 是一套**完整的個人生活管理系統**，不只是待辦清單。長期希望整合：

- 每日任務與目標管理
- 習慣追蹤
- 財務管理
- 心情與生活紀錄
- 個人知識庫與第二大腦
- 願望清單與人生體驗
- 學習與成長紀錄
- 工作、事業與收入管理
- 健康與生活管理
- 人際關係
- 個人資料庫
- ✨ 星光秘境：每日指引（神諭卡、運勢籤、肯定語）、顯化與願望、星座與宇宙能量、自我探索（v2.1 新增，見第 11 章）
- 生活提醒
- 每日、每週、每月回顧

以上是**長期方向**，不代表全部要現在實作。

### 1.2 核心使用理念（已確認）
- 以**彈性待辦清單**為核心，**不使用時間區塊排程**（不排幾點到幾點）
- 依優先順序、截止日期、重要程度整理，可依當天精神與心情彈性調整
- 不要求每天完成所有事情；休息或未完成**不扣點數、不懲罰**
- 以自由、彈性、溫柔、正向成長為核心
- 重要資料的修改或刪除，必須先取得使用者確認

### 1.3 目前有兩個版本（現況紀錄）

| | 下載版（單一 HTML 檔） | Claude 版（發布在 Claude 裡的頁面） |
|---|---|---|
| 開啟方式 | 用瀏覽器直接打開檔案 | 登入 Claude 後開啟頁面連結 |
| 程式 | 同一份 HTML | 同一份 HTML |
| 資料位置 | 這台裝置的瀏覽器 | 這台裝置的瀏覽器＋Claude 帳號私人雲端空間 |
| AI 功能 | 無（按鈕自動隱藏） | 有：透過 Claude 平台，用使用者自己的 Claude 帳號 |
| 跨裝置 | 無，只能匯出／匯入 | 有，但圖片與文件不同步 |
| 兩版之間 | 資料**不會自動互通**，需要手動匯出再匯入 | 同左 |

## 4. 功能技術分類

### A 類：現有 HTML 可以直接實現（純前端，無外部服務）
資料的新增、修改、刪除、排序、篩選、統計、圖表、匯出／匯入、本機備份還原、自動順延（打開時）、逾期標示、習慣打卡與連續天數、財務計算、首頁自訂、籤卡抽取。

### B 類：前端 JavaScript 規則可以完成的「智慧化」功能
**必須在畫面上標示「依規則」，不得稱為 AI。**

| 功能 | 規則做法 | 限制 |
|---|---|---|
| 自動分類／優先 | 關鍵字比對 | 沒出現關鍵字就分錯 |
| 日期判斷 | 明天、下週二、月底、11/20、截止等詞 | 複雜句子判斷不出來 |
| 今日建議 | 依精神、心情、可用時間、優先、逾期挑選 | 不理解任務內容 |
| 習慣降低難度建議 | 7 天打卡少於 3 次時提示，數字除以約 6 | 只會調數字 |
| 財務觀察、週報建議 | 固定條件句 | 不能真正分析原因 |
| 溫柔關心 | 最近 5 筆心情有 3 筆低落，或逾期 5 件以上 | 只看數字 |
| 搜尋 | 關鍵字＋時間詞＋類別詞 | 不懂同義詞 |

### C 類：必須依賴 AI、後端、資料庫或雲端服務
**列入未來擴充。** 目前 HTML 本身不具有真正的 AI 推理、主動學習或跨模組 AI 分析能力。

| 功能 | 需要什麼 | 為什麼純前端做不到 | 目前替代方案 |
|---|---|---|---|
| 理解自然語言、拆解任務、生活分析 | AI 服務 | 推理需要語言模型 | B 類規則；Claude 版有一次性 AI 呼叫（見下方說明） |
| AI 個人記憶、持續學習 | AI＋後端資料庫 | 需要長期儲存與模型處理 | 個人資料庫（使用者自己填寫） |
| 跨模組智慧分析 | AI＋後端 | 同上 | 週報／月報的規則統計 |
| 背景推播、每天固定時間主動關心 | 推播服務＋後端排程 | 頁面關閉後程式不會執行 | 打開 App 時顯示提醒 |
| 雲端同步、多裝置、帳號 | 後端＋資料庫＋身分驗證 | 瀏覽器資料只在單一裝置 | 匯出／匯入；Claude 版私人空間 |
| 圖片內容辨識、文件理解 | AI 服務 | 需要視覺／語言模型 | 手動填寫標題與標籤 |
| 天氣 | 天氣服務 | 頁面不能連外部網站 | 無 |

> **關於 Claude 版**：AI 與同步是借用 Claude 平台的能力，**不是自建後端**。限制如下：
> - 每次呼叫 AI 都是獨立的，不會記得上次對話，也不會自己學習
> - App 關著時不會運作
> - AI 用量計入使用者自己的 Claude 帳號
> - 只有在 Claude 裡開啟時才有效
>
> 是否以此作為正式路線，待 Q-A 確認。

## 5. 核心規則（已確認需求的詳細規格）

### 5.1 待辦資料欄位（現況）
每筆任務都有以下欄位，舊欄位保留且同步：

| 新欄位 | 說明 | 對應舊欄位 |
|---|---|---|
| id | 永久不變 | id |
| title / description | 任務內容與備註 | text |
| category | 工作、事業、內容創作、財務、學習、生活 | cat |
| priority | 高、中、低 | pri |
| scheduledDate | 目前安排日期（YYYY-MM-DD，裝置當地日期） | — |
| dueDate | 截止日期，可為 null，**系統永不自動修改** | — |
| createdAt | 原始建立時間，**永不修改** | created |
| completedAt / status | 完成時間；open 或 done | doneAt / done |
| sortOrder | 使用者排序 | — |
| rolloverCount / rolloverHistory | 自動順延天數與紀錄 | — |
| mins / goalId / updatedAt | 預估時間、關聯目標、更新時間 | — |

### 5.2 自動順延規則（已確認）
1. 未完成且 scheduledDate 早於今天的任務，移到今天
2. 使用**同一筆任務、同一個 id**，不建立新任務
3. 保留 createdAt 與 dueDate，不修改
4. rolloverHistory 新增一筆 `{from, to, days, at}`，rolloverCount 增加天數
5. 已完成的任務不順延
6. 可以重複執行：同一天重新整理不會重複順延
7. 執行時機：打開 App、回到頁面、頁面開著跨過午夜（每分鐘檢查）
8. **限制**：App 關著時不會執行，下次打開時一次補上天數

### 5.3 截止日期與逾期（已確認）
- 截止日期和安排日期是兩個獨立欄位
- dueDate 早於今天且未完成 → 顯示「已逾期・原截止 MM/DD」，同時仍然每天順延
- 只有使用者自己可以修改截止日期

### 5.4 手動修改日期
直接更新 scheduledDate，不寫入 rolloverHistory，和自動順延分開記錄。

### 5.5 排序
使用者拖曳後自動儲存，新任務放在底部，系統不自動重排。今日建議只挑選任務，顯示順序仍依使用者排序。

### 5.6 每日籤卡 → 併入星光秘境
v2.0 的籤卡規格已由第 11 章取代：
- 每日運勢籤：見 11.6「🧧 每日運勢籤」
- 大天使神諭卡：見 11.6「👼 大天使神諭卡」

舊的 24 張籤卡紀錄**保留**，顯示為「舊版籤」（見 11.2 C9）。

### 5.7 AI 個性與確認原則（已確認）
- 溫暖、療癒、理解使用者；可以陪伴、分析、提醒、建議；不批評、不施壓、不製造罪惡感
- 任何新增、修改、刪除都要先顯示預覽，由使用者按確認後才寫入
- 只有已授權的固定規則（每日順延、每日自動備份、點數累積）可以自動執行

## 6. 資料保護與程式相容性規範（必須遵守）

### 6.1 目前的儲存位置

| 位置 | 名稱 | 內容 |
|---|---|---|
| localStorage | `lifebox_v1` | 全部主資料（**名稱永不更改**） |
| localStorage | `lifebox_v1_backups` | 本機備份，最多 8 份 |
| localStorage | `lifeos_device` | 裝置識別碼（同步用） |
| IndexedDB | `lifeos_files` | 第二大腦的圖片與文件 |
| Claude 私人空間（只有 Claude 版） | `data/users/<id>/lifeos_*` | 主資料分段副本 |

### 6.2 主資料結構（schemaVersion 4）
`todos, results, plans, cards, draft, habits, habitRecords, moodRecords, journalEntries, reviews, goals, wishlist, personalProfile.entries, fin{accounts, tx, budgets, savings}, knowledge, reward{ledger, rules, rewards, redemptions, badges, deco}, settings{home, dismissed, lastAutoBackup, aiUseProfile}, schemaVersion, lastRolloverDate, savedAt`

### 6.3 修改程式時的規範
1. **不更改** `lifebox_v1` 的名稱，不刪除任何既有欄位；欄位改名時新舊並存並同步
2. 資料格式變更必須遞增 `schemaVersion`，用版本化遷移處理
3. 遷移只能**新增或補齊**欄位，必須可重複執行，結果相同
4. 遷移前先備份；**備份失敗就停止遷移**（待修正 P0-2）
5. 讀取失敗時**不得寫入主資料**，改進入復原模式（待修正 P0-1）
6. 任何「取代」類操作（匯入取代、還原、雲端載入）前，先自動備份目前資料
7. 匯入合併以 id 去重；心情、回顧、建議、籤卡以日期去重
8. 刪除功能一律提供確認或復原
9. 不在背景或啟動時刪除使用者資料
10. 每次交付都附舊資料讀取測試：用前一版格式的資料開啟，確認數量與內容一致

### 6.4 錯誤處理
- 儲存失敗（空間不足）：提示使用者，不清空資料
- 雲端同步失敗：保留本機資料，下次再試
- 同步衝突：不直接覆蓋；先備份本機，再載入較新的資料（現況），並提示使用者

## 11. ✨ 星光秘境 Starlight Sanctuary（擴充模組）

### 11.1 定位與原則
- **定位**：個人靈性探索、每日指引、顯化許願與宇宙能量探索中心。這不是把「抽卡」改名，而是升級成有分類、互動、紀錄與個人化的工具區
- **氛圍**：神秘、療癒、有儀式感，同時高級、精緻、不俗氣
- **內容性質**：所有運勢、神諭、星座、數字解讀都屬於**娛樂與自我反思**，頁面要註明，不宣稱能預測未來
- **誠實原則**：內容來自內建內容庫與固定規則；需要星曆、AI 或外部資料的功能，必須標示技術依賴，不能用假資料冒充即時運算
- **版權**：神諭卡、籤詩、肯定語、提問、解讀文字都要**原創**，不複製市售卡牌（例如市面上的大天使神諭卡）的圖文；大天使名稱屬於傳統宗教文化，可以使用
- **不破壞現有系統**：不重做其他頁面的 UI、不讓首頁或導覽列變擁擠、不清除既有資料

### 11.6 功能規格

技術依賴標記：
- **【內容庫】**：內建原創文字＋依日期的固定規則，純前端
- **【計算】**：需要天文或數學計算，純前端可做，但必須用測試驗證
- **【外部】**：需要 AI、外部 API 或後端

#### 🌌 今日宇宙訊息【內容庫】
- 每天顯示：主題、宇宙訊息、肯定語、行動建議、幸運色、幸運數字，以及指引卡入口
- 以「日期」為種子從內容庫挑選，同一天重開結果相同，隔天換新
- 標示：「今日訊息來自內建內容庫」

#### 👼 大天使神諭卡【內容庫】
- **卡組**：原創卡組（建議 44 張，數量待確認 Q-S）。每張卡有：卡名、守護天使（傳統大天使名，如米迦勒、拉斐爾、加百列、烏列爾）、核心訊息、深度解讀、可以思考的問題、今日行動、一句鼓勵自己的話，並依 8 個主題各有適用重點
- **抽卡模式**：
  - **每日單張**：每天一張，保存在紀錄中
  - **自由抽卡**：不限次數，每次都保存，可刪除
  - **主題抽卡**：❤️ 愛情與關係、💰 財富與豐盛、💼 工作與事業、🌱 自我成長、🕊️ 療癒與放下、✨ 人生方向、🌍 旅行與自由、🌸 當下需要的訊息
- **互動**：洗牌與翻牌動畫、收藏卡片、在抽卡結果寫下心得
- **隨機性**：每日卡用日期種子固定；自由抽卡使用瀏覽器亂數

#### 🧧 每日運勢籤【內容庫】
- **等級**：大吉、吉、中吉、小吉、平（順序與比例見 Q-H）
- **每支籤包含**：籤名、籤詩（原創四句）、今日整體、財運、愛情運、工作運、健康與生活提醒、幸運色、幸運數字、今日宜、今日忌、今日行動建議
- **規則**：每天一支；保存紀錄；舊版 24 張紀錄照常顯示，標示為「舊版籤」
- 「今日忌」只寫溫和的提醒（例如「忌熬夜」），不寫令人不安的內容

#### 💌 每日肯定語【內容庫】
- **內容**：依日期顯示一句（內容庫建議 365 句以上），可以收藏、複製文字、寫下當下感受
- **首頁**：可取代首頁的「今日療癒語錄」（Q-L）

#### 🃏 三張牌指引【內容庫】
- **三種牌陣**：
  - 過去／現在／未來
  - 問題／阻礙／建議
  - 我需要知道的事／我需要放下的事／我可以採取的行動
- **使用卡組**：大天使神諭卡
- **解讀**：每張牌依所在位置有一段解讀，最後加上整體統整。統整由規則組合而成，不是 AI 生成
- **紀錄**：可以先寫下想問的問題，結果連同問題一起保存

#### 🌠 顯化許願池【內容庫不需要，純資料管理】
- **欄位**：名稱、描述、分類（9 類）、圖片（一到多張）、建立日期、目標日期、為什麼想實現、實際行動清單、顯化進度（0～100%）、狀態（🌱 正在顯化／✨ 正在行動／🌷 部分實現／🏆 已實現／🤍 暫時放下）、心得紀錄
- **操作**：新增、編輯、刪除（需確認）、更新進度與狀態
- **與 Life OS 整合**：
  - 「實際行動」可一鍵轉成待辦任務（先預覽、確認後才建立，並保留關聯）
  - 願望可以連結到既有的目標
- **與現有「願望清單」的關係**：見 C2、Q-I

#### 🎯 願景板
- **呈現**：Pinterest 風格的瀑布流牆面（CSS 多欄排版），每張卡有圖片、文字備註和分類
- **操作**：可以拖曳調整順序、連結許願池裡的願望、標記為已實現
- **圖片**：存在 IndexedDB，存入前自動壓縮（長邊 1600px、JPEG 品質約 0.85）
- **「選擇圖片」**：提供內建的漸層與星空插畫底圖，由 CSS 或 SVG 畫出，不使用有版權疑慮的照片

#### ✍️ 顯化日記【內容庫：寫作提示】
- **功能**：每日書寫、未來情境描述、顯化肯定語、連結願望、依日期搜尋、收藏
- **寫作提示**：內建一組提示語，例如「如果今天的願望已經實現，你的生活會有什麼不同？」

#### 🤎 感恩日記
- **功能**：每天寫三件感恩的事，也可以額外自由新增，並加上心情標籤
- **回顧**：可以查看歷史紀錄，月度回顧會統計這個月的感恩數量、常出現的字詞和心情分布
- **與心情紀錄的關係**：見 Q-J

#### 🏆 顯化成功紀錄牆
- **建立方式**：願望標記為「🏆 已實現」時，詢問是否加入成功紀錄牆；也可以手動新增
- **每筆紀錄包含**：願望名稱、實現日期、**願望原始內容**（加入時保存一份快照）、實現過程、照片、心得、當時心情、想對過去的自己說的話
- **呈現**：照片牆與紀錄卡兩種模式，可依年份或願望分類篩選，並顯示累積實現數量
- **關聯**：成功紀錄記下來源願望的 id，願望也記下成功紀錄的 id。**原本的願望保留不刪除**；刪除成功紀錄時，願望狀態不變

#### ♈ 星座運勢【內容庫】
- **功能**：設定個人星座後，首頁優先顯示；提供每日、每週、每月運勢，內容分為整體、愛情、財運、工作，以及今日提醒
- **內容產生方式**：由原創文字片段，依「星座＋日期／週／月」固定組合而成
- **必須標示**：「內建娛樂性運勢內容，不是即時星象計算」
- **紀錄**：查看當下保存一份，方便日後回顧

#### 🪐 個人星盤【計算＋內容庫】

| 項目 | 可行性 | 做法 | 風險 |
|---|---|---|---|
| 太陽星座 | 高 | 出生日期對照星座日期 | 交界日要依出生年份與時間判斷，否則可能差一個星座 |
| 月亮星座、行星位置 | 中高 | 使用開源天文計算程式庫（例如 astronomy-engine，MIT 授權） | 程式庫需要從 CDN 載入，或直接打包進 HTML（檔案會變大） |
| 上升星座、十二宮位 | 中 | 由出生時間、地點經緯度、時區計算 | 出生時間要準確；台灣曾在部分年份實施日光節約時間；宮位制要先決定（Q-N） |
| 出生地點 | — | 內建城市清單＋手動輸入經緯度 | 若要用地名查座標，需要外部 API（【外部】） |
| 星盤解讀 | 中 | 原創「行星×星座」「行星×宮位」解讀片段 | 只能做到元素組合式的解讀，不是專業占星師的綜合判讀 |

**驗收**：至少用 5 組已知的出生資料，和公開的星盤工具結果比對，誤差需在可接受範圍內，才能上線。驗證完成前，只開放「資料欄位＋太陽星座」。

#### 🌕 月相日曆【計算】
- **月相計算**：新月、上弦、滿月、下弦，用天文演算法計算（可以用程式庫，也可以自己實作公開的天文公式），換算成台灣時間（UTC+8）
- **驗收**：和中央氣象署或天文台公布的 2026～2027 年月相時刻比對，日期必須一致
- **內容**：每個月相有主題說明，新月提供許願書寫，滿月提供釋放儀式步驟（內容庫），另有個人月相日記
- **新月提醒**：只會在打開 App 時，顯示在首頁的提醒中；背景推播屬於【外部】

#### 🔢 天使數字解讀【內容庫】
- **收錄**：111～999 與 1111、2222，並可擴充其他數字
- **功能**：每個數字有象徵與生活提醒，可以搜尋數字，也可以記錄看到數字的日期、情境與心情，形成個人數字紀錄

#### 🪞 靈魂提問卡【內容庫】
- **題庫**：依日期每天出一題，題庫建議 120 題以上，分類為自由、關係、恐懼、渴望、放下、自我價值
- **功能**：自由回答、查看歷史答案、收藏，並可以查看「一年前的今天你怎麼回答」

#### ᚱ 盧恩符文【內容庫】（細節待確認 Q-M）
- **規劃**：使用 24 個古弗薩克符文，提供單顆抽取與三顆排列，解讀以原創文字撰寫
- **符文含義**：每個符文的名稱與傳統含義都有公開的學術資料，解讀文字需要原創

#### ☯ 易經卦象【計算＋內容庫】（細節待確認 Q-M）
- **起卦**：採用三錢法（每爻擲三枚錢幣），機率可以驗證；也可以支援手動輸入每一爻
- **資料**：64 卦依文王卦序排列，資料需要和公開對照表逐一核對
- **變爻**：有變爻時，會轉成之卦
- **文字**：《易經》原文已屬公有領域，可以收錄；白話解讀需要原創
- **驗收**：64 卦的卦象與卦名要全部和對照表逐一比對；起卦結果的統計分布要符合三錢法的理論機率

#### 📖 我的探索紀錄
- **統一入口**：抽卡、運勢籤、星座、月相、顯化日記、感恩日記、靈魂提問、天使數字、成功紀錄
- **功能**：依日期、工具分類篩選，關鍵字搜尋，收藏、編輯、刪除（需確認）
- **匯出個人紀錄**：可以匯出 JSON 檔（可再匯入），以及方便閱讀的文字檔；在 Claude 版裡使用 Claude 的下載確認
- **資料保存方式**：各工具的資料分開保存，透過共同的 `date`、`tool`、`tags` 欄位搜尋

### 11.7 資料結構

**存放位置**：放在既有的 `lifebox_v1` 裡，作為獨立的資料區 `star`。這樣原本的備份、匯出／匯入、Claude 版同步都能直接涵蓋，不需要另外處理；不新增獨立的 localStorage 名稱。

主資料版本 `schemaVersion` 會從 4 升到 5。遷移只新增空的 `star` 資料區，不修改其他資料，遷移前照規範先自動備份。

```js
S.star = {
  version: 1,                      // 星光秘境自己的版本，方便之後單獨遷移
  profile: {
    zodiac: null,                  // "aries" … "pisces"
    birth: { date:null, time:null, place:null, lat:null, lng:null, utcOffset:null },
    settings: { homeShows:"affirmation" }   // 首頁顯示哪一項（Q-L）
  },
  draws: [ {                       // 神諭卡、三張牌、運勢籤、盧恩、易經都存在這裡
    id, tool:"oracle"|"spread"|"fortune"|"rune"|"iching",
    mode:"daily"|"free"|"theme", theme:null, spread:null, question:"",
    cards:[{ deck:"oracle-v1"|"fortune-v1"|"rune-v1"|"iching", cardId, position, reversed:false, lines:[] }],
    date:"YYYY-MM-DD", at, fav:false, note:"", tags:[] } ],
  affirmations: [ { id, date, affId, fav, feeling, at } ],

    id, title, desc, category, images:[fileId], createdAt, targetDate,
    why, status:"manifesting"|"acting"|"partial"|"achieved"|"paused", progress:0,
    actions:[{ id, text, done, taskId:null }],
    notes:[{ id, at, text }], goalId:null, legacyWishlistId:null, successId:null, updatedAt } ],
  vision: [ { id, fileId|null, preset|null, caption, category, wishId:null, order, achieved:false, createdAt } ],
  manifestJournal: [ { id, date, promptId, text, wishId:null, fav, tags:[], at } ],
  gratitude: [ { id, date, items:["","",""], extra:[], moodTag, linkedJournalId:null, at } ],
  successes: [ { id, wishId, title, achievedDate, originalSnapshot:{…},
                 process, photos:[fileId], reflection, mood, toPastSelf, category, createdAt } ],
  horoscopeLog: [ { id, date, sign, period:"day"|"week"|"month", textSnapshot, at } ],
  moonJournal: [ { id, date, phase, intention, release, text, at } ],
  angelNumbers: [ { id, number, date, context, mood, note, at } ],
  soulQA: [ { id, date, questionId, answer, fav, at } ]

```

**資料規則**
- 每筆都有 `id`，匯入合併時以 `id` 去重；每日唯一的紀錄（每日卡、每日籤、肯定語）以 `date` 去重
- 跨模組關聯只存對方的 `id`（`taskId`、`goalId`、`wishId`、`successId`），不複製整筆資料；刪除一方時，另一方只把關聯清空
- 成功紀錄的 `originalSnapshot` 是加入當下的願望副本，之後即使願望被修改，成功紀錄仍保留原始內容
- 圖片一律存 IndexedDB `lifeos_files`，主資料只存 `fileId`；匯出備份時一起打包
- 內容庫（卡片文字、題庫、星座片段）寫在程式裡，**不存進使用者資料**；紀錄只存卡片編號，並在卡組名稱中標示版本（例如 `oracle-v1`），之後改版也不會讓舊紀錄對錯卡

**容量估算**

| 項目 | 存放位置 | 每筆或總量 | 一年用量（每天使用） |
|---|---|---|---|
| 文字紀錄 | localStorage | 約 0.3～1KB | 約 1MB 以內 |
| 圖片 | IndexedDB | 壓縮後每張約 150～400KB | 視張數而定 |

- localStorage 通常只有約 5MB，所以圖片**不能**放進 localStorage
- 內容庫會讓 HTML 檔變大，預估從目前約 230KB 增加到 500～700KB

## 12. v2.2 決策紀錄與實作狀態（2026-11-13）

### 已確認
- **Q-H 運勢等級**：大吉、中吉、吉、小吉、平平、需要加油（依此順序）。

- **Q-Q 每日內容**：每個人各自隨機（依個人 seed），同一人同一天固定。

### 預設決定（可再調整）
- 星光秘境活動不給成長點數。
- 首頁「今日療癒語錄」改為「今日肯定語」；新增「今日宇宙訊息」模組（預設隱藏）。
- 第一階段只做三張牌牌陣。
- 感恩日記獨立，可勾選同步到心情日記。
- 盧恩符文、易經：規格待補，尚未開放（不可點）。
- 個人星盤：只算太陽星座並保存出生資料；月亮、上升、宮位、行星尚未開放。

### 資料保護（P0，已完成）
- 主資料無法讀取 → 保護模式：暫停所有儲存、另存原始內容，提供下載原始內容／從備份還原／確認後重新開始。
- 升級前備份失敗 → 停止升級並暫停儲存，請使用者先匯出。
- 待辦清單內的直接刪除 → 5 秒內可「復原」。
- 資料版本 4 → 5（只新增 `star` 資料區與願望欄位，不刪除任何舊資料）。
